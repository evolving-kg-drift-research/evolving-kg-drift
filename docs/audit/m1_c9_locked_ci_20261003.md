## Implemented

- Locked dependency validation now requires exact pins for every declared
  `project.dependencies` entry and every `build-system.requires` entry. An
  invalid or absent pin is converted to an initialization blocker before a run
  directory is created.
- Run config bundling reads the protocol only from authoritative
  `configs/protocol_v1.yaml`. The legacy `config/protocol.yaml` is never a
  fallback. A locked run with a missing or malformed authoritative protocol is
  rejected; an unlocked fixture/inventory bundle may record that no protocol
  was supplied without inventing one.
- The default CI workflow runs code checks and G1 helper conformance with
  `--code-checks`; it does not call artifact-backed G1/G2 verification. A
  regression test guards this scope. Scientific gate CLIs still require an
  explicit run and return `BLOCKED` with a nonzero status when evidence is
  absent.
- Existing locked checks remain in force for a frozen baseline, local adapter,
  model/tokenizer/runtime fingerprints, explicit decoding values, immutable
  cache replay, cache tampering, run/config/code hashes, and gate/artifact
  lineage.
